Git常用命令学习笔记

Git 是日常开发里最常用的版本控制工具。理解它时，可以先记住一个简单流程：

下面按照使用场景整理常见命令，方便以后查阅。

全局设置与初始化

命令 作用 备注
git config --global user.name xxx 设置全局用户名 信息记录在 ~/.gitconfig
git config --global user.email xxx@xxx.com 设置全局邮箱 提交记录会带上该邮箱
git init 将当前目录初始化为 Git 仓库 会生成隐藏的 .git 目录
git clone git@git.acwing.com:xxx/XXX.git 克隆远程仓库 会把项目下载到当前目录

日常提交

命令 作用 备注
git status 查看仓库状态 最常用，提交前后都建议看一眼
git add XX 将文件加入暂存区 XX 可以是文件或目录
git add . 暂存当前目录下的修改 适合一次性提交多个文件
git commit -m "备注信息" 提交暂存区内容 备注尽量写清楚本次改动
git push -u origin branch_name 首次推送并关联远程分支 之后可直接用 git push
git push 推送当前分支 需要已经设置 upstream

查看与对比

命令 作用 备注
git diff XX 查看文件相对暂存区的修改 适合提交前检查
git log 查看当前分支提交历史 默认信息较详细
git log --pretty=oneline 单行查看提交历史 方便复制版本号
git reflog 查看 HEAD 移动历史 可找回被回退前的版本号
git branch 查看本地分支 星号所在分支是当前分支
git pull 拉取并合并远程当前分支 相当于更新本地代码

撤销与删除

命令 作用 备注
git rm --cached XX 从 Git 索引中移除文件 文件仍保留在本地，只是不再被 Git 管理
git restore --staged XX 将文件从暂存区移出 撤销 git add
git restore XX 撤销工作区修改 只适用于尚未提交的修改
git checkout -- XX 撤销工作区修改 老写法，效果类似 git restore XX

git restore XX 和 git reset --hard 都可能丢失未保存的修改，执行前最好先 git status 确认。

版本回退

命令 作用 备注
git reset --hard HEAD^ 回退到上一个版本 HEAD~ 也表示上一个版本
git reset --hard HEAD^^ 往上回退两个版本 多个 ^ 表示多次回退
git reset --hard HEAD~100 往上回退 100 个版本 数字可替换
git reset --hard 版本号 回退到指定版本 版本号来自 git log 或 git reflog

重点是：回退后如果想再次回到回退前的版本，需要知道那个版本号。
如果回退前忘记复制版本号，可以用 git reflog 查看 HEAD 的移动历史，再找到原来的提交号。

本质上，git reset --hard 版本号 是让当前分支直接跳到某个提交；只要版本号还找得到，就既可以回到旧版本，也可以重新回到回退前的版本。

远程仓库

命令 作用 备注
git remote add origin git@git.acwing.com:xxx/XXX.git 关联远程仓库 origin 是常用远程仓库名
git push origin branch_name 推送指定本地分支 不一定设置 upstream
git push --set-upstream origin branch_name 推送并建立分支关联 等价于常见的首次 git push -u
git pull origin branch_name 拉取远程指定分支并合并到当前分支 注意当前所在分支
git push -d origin branch_name 删除远程分支 删除前确认分支是否还需要
git checkout -t origin/branch_name 拉取远程分支到本地并跟踪 适合本地还没有该分支时
git branch --set-upstream-to=origin/branch_name1 branch_name2 设置本地分支对应的远程分支 之后可直接 git pull 或 git push

分支管理

命令 作用 备注
git branch branch_name 创建新分支 不会自动切换
git checkout branch_name 切换分支 老写法
git checkout -b branch_name 创建并切换到新分支 常用于新功能开发
git merge branch_name 将指定分支合并到当前分支 先确认自己所在分支
git branch -d branch_name 删除本地分支 一般用于分支已合并后

stash 临时保存

命令 作用 备注
git stash 临时保存工作区和暂存区修改 适合当前工作未完成但要切分支
git stash list 查看 stash 列表 栈顶一般是 stash@{0}
git stash apply 恢复栈顶修改但不删除 stash 可重复应用
git stash drop 删除栈顶 stash 确认不需要后再删
git stash pop 恢复栈顶修改并删除 stash 最常用

几个常见操作例子

1. 新项目第一次提交

这套流程表示：先初始化仓库，再查看状态，把 README.md 放入暂存区，最后提交到本地仓库。

2. 新建分支完成一次开发并推送

第一次推送新分支时建议带上 --set-upstream，之后在这个分支上就可以直接使用 git push。

3. 当前修改没做完，但需要切换分支

这里先用 git stash 把未完成的修改临时存起来，切到 main 更新代码，再回到原分支恢复修改。

4. 回退到旧版本，再回到回退前版本

假设 a1b2c3d 是旧版本号，第一次 reset 会让代码回到旧版本。
如果之后想回到回退前的状态，可以用 git reflog 找到原来的版本号，例如 e4f5a6b，再执行一次 git reset --hard e4f5a6b。

实际使用时，版本号不需要写完整，通常复制前 7 位左右即可；只要 Git 能唯一识别这个提交就行。
